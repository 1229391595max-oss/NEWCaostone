# NEWCaostone Roadmap

This roadmap starts from the private team-preview scope. Priority indicates execution order, not a promise that hosted or Production acceptance already exists.

## P0 — Close and share safely

### Finish Admin Task 12

- Complete the separately authorized read-only authority refresh.
- Prove the complete current Admin/AI recovery-adoption contract before changing local authority.
- Run hosted Admin acceptance only from the exact reviewed source and package.
- Record deployment, hosted verification, AI state, and Production state as separate evidence.
- Never replay consumed or retired recovery packages.

**Completion evidence:** exact source and image identity, sanitized hosted receipt, updated authority/status/handoff documents, and explicit AI/Production boundaries.

### Establish GitHub collaboration

- Publish the reviewed source and teammate documents to the private `NEWCaostone` repository.
- Protect the default branch and require review for later changes.
- Add a basic CI workflow after the first preview, using the existing Python, Node, Ruff, and authority checks.
- Document the minimum local development and review workflow for teammates.

**Completion evidence:** private visibility, exact remote SHA, reviewed default branch, passing CI, and no secret or local-artifact exposure.

## P1 — Complete the next product capabilities

### Qualify and enable real AI through Admin

- Keep the real key out of Git, chat, logs, database fields, browser storage, and response bodies.
- Use the protected Admin workflow, current-password reauthentication, one-time candidate input, exact Key Vault version, and database channel authority.
- Qualify the fixed provider/model under a bounded paid-smoke authorization.
- Verify Operator and Demo switches independently, then rehearse emergency disable and rollback.
- Preserve deterministic data and evidence as the authority for every answer.

**Completion evidence:** exact hosted acceptance receipt, safe key fingerprint metadata only, bounded provider result, budget/limit evidence, emergency-disable proof, and no key leakage.

### Support current Chinese marketplace workbooks formally

- Review the isolated offline repair as evidence, not as an automatic merge source.
- Add narrowly scoped adapters for the actual workbook sheets, headers, formulas, and package parts the team needs.
- Keep XLSX/ZIP safety checks, size limits, mapping preview, idempotency, and immutable commit behavior.
- Report failures by stage: upload, package safety, recognition, mapping, standardization, or commit.

**Completion evidence:** representative March/April and supported marketplace workbooks pass the formal Operator pipeline and deterministic calculations; unsupported variants fail with stable safe errors.

### Add invitation-only multi-account tenancy

- Design users, workspaces, memberships, roles, session revocation, and one-time invitation/reset flows.
- Keep public Demo identity separate from formal accounts.
- Enforce workspace identity on the server, PostgreSQL access, service queries, Blob paths, actions, chat history, and budgets.
- Start with platform owner, workspace owner, analyst, and viewer roles; do not add public registration.

**Completion evidence:** negative cross-workspace tests, role matrix tests, session-revocation tests, Blob/data isolation proof, and hosted account acceptance.

## P2 — Expand after the foundations

### Improve import operations and adapter coverage

- Add clearer task-state and error guidance to Admin.
- Extend verified adapters only from representative evidence.
- Track import, analysis, release, and maintenance states in one operational view.
- Preserve completed/failed task records as immutable evidence and require a new workflow for retry.

### Assess external opportunity and marketplace connections

- Design Product Opportunity search as a separate evidence-sourced capability.
- Evaluate Google Trends or another approved source only after terms, API availability, privacy, cost, and failure behavior are known.
- Treat Shopee/Mercado Livre connections as explicit provider integrations with permissions, tenant scope, rate limits, and reconciliation evidence.
- Keep AI explanation separate from provider facts and deterministic calculations.

## Explicitly deferred

The team preview does not include:

- public self-registration;
- subscription billing;
- per-user API keys;
- enterprise SSO;
- microservice decomposition;
- multi-region infrastructure;
- high-concurrency autoscaling work beyond current safety limits;
- autonomous purchasing, pricing, advertising, inventory, or marketplace actions;
- claims that local or synthetic evidence proves Production readiness.
