## 1. 文档目的

本设计以 `v0.1.0` 为主稿，固化 NEWCaostone 本次 Azure Demo 的产品范围、用户模式、零真实数据边界、候选模块核验规则、AI 使用方式、数据库问答 Chat Box、行动卡闭环、部署边界和验收证据。最高优先级是：在不牺牲证据、安全和持久化边界的前提下，最快、最稳地完成复刻和 Azure 上线，同时减少零散人工授权中断并保持 NEWCaostone 工作区干净。

本文件是已批准的权威设计。本版已经对 CAPTSONE 的受版本控制设计文件、正式前端入口和相关 AI 模块完成只读设计检查，但这不代表：

- 已经把任何 CAPTSONE 模块认定为可复用、复制到 NEWCaostone 或完成运行验证；
- 已经完成算法、代码、测试或数据库；
- 已经创建 Git 仓库或提交；
- 已经部署 Azure URL；
- 已经通过本地、CI、Azure 或浏览器验收。

本设计已由用户批准，可以拆分实施计划并执行已单独授权的 Stage 0 本地初始化与只读审计。实施计划仍须用户批准后才能进入功能编码；当前阶段不读取真实业务数据，不对旧系统做任何写操作，不安装功能依赖、运行候选写入型测试或部署。

## 2. 已确认边界

以下内容视为本版本已确认输入：

1. 本次只制作和上线 Demo，没有任何真实数据。
2. 以 `v0.1.0` 的单操作者、匿名观众、PostgreSQL、Blob、确定性分析和行动卡设计为主。
3. 功能范围是现有有效功能，加上：
   - AI 辅助新品预测；
   - 利润归因；
   - 可询问当前合成数据库经营问题的 `Ask BizPulse / 数据问答` Chat Box；
   - 完整行动卡；
   - 可访问并经过验收的 Azure URL。
4. CAPTSONE 只读，所有新增、复制、修改、测试产物和文档都只能位于 NEWCaostone。
5. 后续可以选择性复用旧实现，但必须先证明候选模块不是旧版本、废稿、备份或未接入运行路径的代码。
6. 行动卡以人工审批、调整、驳回、文件导出和结果复盘为终点，不直接写入 Shopee、UpSeller、广告平台或采购系统。
7. 全站 AI 使用操作者提供的一把专用临时 OpenAI API Key，首发固定 `gpt-5.4-mini-2026-03-17` 和 `reasoning.effort: low`。
8. 观众在有效会话内不显示固定提问次数额度；系统仍限制单次长度、并发速度和全站总费用。
9. 演示结束后撤销临时 API Key，并从 Azure 服务器配置中删除。
10. 新品预测保持本文件已有的“合成数据相似 SKU + 人工确认 + 确定性三情景 + AI 解释”方案；本次不导入、不调用、不抓取 Google Trends，也不接入其他在线市场数据源。
11. Chat Box 面向当前会话固定的合成数据库和已完成分析，不是 SQL 控制台；模型不得接收数据库凭据、任意 schema 或执行自由 SQL。

## 3. 本版本相对 v0.1.0 的关键修订

### 3.1 数据边界收紧

`v0.1.0` 中“虚构、修改或脱敏数据”的表述扩大了边界。本版本统一改为：

- 允许确定性生成的合成数据；
- 允许人工编写的虚构数据；
- 不允许真实订单、真实客户、真实店铺、真实 SKU、真实广告、真实成本、真实库存或真实财务数据；
- 不允许由真实数据修改、脱敏、打乱、截断、聚合或匿名化得到的数据；
- 不允许从旧系统截图、导出物、日志或数据库复制真实值作为演示样本；
- 不允许使用真实账号标识、联系人、地址、订单号、店铺 ID、密钥或连接信息。

因此，本次 Demo 的“无真实数据”是来源级约束，不只是页面隐藏或字段脱敏。

### 3.2 候选模块必须经过来源权威核验

本版本补充来源权威、运行可达性、版本新旧、迁移链和测试证据规则，避免因为文件名、旧文档或界面存在就复用废稿。

### 3.3 AI 设计保留已确认的固定模型

首发模型固定为 `gpt-5.4-mini-2026-03-17`，以减少演示结果漂移。模型值由服务器配置执行，浏览器和观众不能选择或切换。更换模型需要先运行同一固定评估集，并在新设计版本中记录，不能在已验收版本上静默改变。

### 3.4 新品预测和利润归因补足产品级算法边界

本版本定义输入、输出、证据状态、场景和失败路径。后续算法子规格负责精确公式，但不得改变本设计中的权威边界。

### 3.5 不纳入真实数据接管

真实数据迁移、正式客户使用、Production 安全认证、正式灾难恢复和外部平台写入均不属于本次交付。未来如需接管真实数据，必须另立新版本设计和独立授权门。

### 3.6 增加数据库问答 Chat Box

旧项目当前正式实现包含一次性 Operating Briefing 和单个新品机会 AI 解读，但明确排除了自由对话；代码中也不存在通用数据库 Chat Box。本版新增 `Ask BizPulse / 数据问答`，让用户用自然语言询问当前合成数据库中的销售、广告、库存、成本、利润、补货、数据质量和行动卡问题。

Chat Box 使用“封闭意图计划 → 服务端白名单查询 → 确定性结构化结果 → AI 解释”的链路。它不把 SQL、数据库连接或任意工具交给模型，也不允许模型改变数字、证据或状态。

### 3.7 明确排除 Google Trends

本版不包含 Google Trends API、CSV 导入、人工上传、非官方接口、`pytrends`、网页抓取或浏览器模拟。旧 Product Opportunity 设计中的 Google Trends CSV/API 路径不是本次复用目标。若保留现有新品机会展示，只使用内置、版本化、明确标注的合成市场快照，不进行在线刷新。

### 3.8 最快稳定交付与连续执行

复用核验只覆盖本次所需的正式垂直模块，并设置时间上限；超过时限仍无法证明当前、可达、可迁移和可测试的候选，直接在 NEWCaostone 重建。本地实施、测试和文档在批准的实施计划范围内连续执行；Azure 变更集中到一个可审计上线授权包，销毁性清理另设一个授权包，避免每条普通命令都暂停确认。

## 5. 产品模式与权限

### 5.1 匿名观众 Demo

观众通过 Azure 公开 HTTPS URL 进入，不注册、不登录、不上传文件。

观众可以：

- 查看当前已发布的纯合成数据版本；
- 浏览现有分析页面；
- 查看新品预测和利润归因；
- 在 `Ask BizPulse / 数据问答` 中选择推荐问题或输入有限自由文本，询问当前会话固定的合成数据库；
- 在自己的临时会话内模拟批准、调整或驳回行动卡；
- 刷新后在会话有效期内继续。

观众不可以：

- 上传、编辑、删除或发布数据；
- 指定任意数据版本、工作区或会话范围；
- 查询数据库 schema、系统表、原始整行、密钥、连接信息或任意 SQL；
- 查看其他观众的对话或行动状态；
- 修改公共演示数据；
- 触发真实采购、广告或平台操作；
- 访问操作者路由、部署配置或管理接口。

### 5.2 单一操作者

系统只有一个受保护的操作者账户和一个演示工作区。首发不建设注册、邀请、团队或角色管理。

操作者可以：

- 登录受保护入口；
- 使用内置纯合成数据集；
- 上传经过人工确认的纯合成 Excel/CSV，以演示现有导入功能；
- 运行识别、映射、标准化、质量检查和原子提交；
- 查看、比较和发布演示数据版本；
- 使用 AI、新品预测、利润归因和行动卡；
- 使用与操作者当前数据版本绑定的数据库问答，并从合格回答显式创建待审行动卡草稿；
- 导出演示采购/广告任务文件；
- 记录合成结果复盘。

操作者认证采用服务器验证的单账户机制，凭据或身份配置只存在服务端。是否复用旧认证实现必须通过第 7 节的候选核验门。

### 5.3 演示会话

每位观众获得服务端生成、不可预测的会话标识，通过安全 Cookie 关联浏览器。

- 空闲有效期：30 分钟；
- 绝对有效期：2 小时；
- 刷新、前进、后退：恢复同一会话；
- 关闭标签页：有效期内允许恢复；
- 主动结束：立即清理该会话的对话摘要和模拟行动；
- 到期：后台清理并引导创建新会话；
- 应用重启：未过期会话从 PostgreSQL 恢复；
- 数据版本：进入会话时固定，不随操作者后续发布而改变。

会话只保存必要状态，不复制整套数据。

## 6. 功能范围合同

### 6.1 “现有功能”的定义

“现有功能”不能由旧文档、菜单名称、截图或孤立代码文件定义。只有同时满足以下条件的能力才进入复用候选清单：

1. 位于后续选定并记录的不可变源代码提交中；
2. 能从正式应用入口、正式路由或正式前端入口到达；
3. 依赖的数据库对象位于一致、可执行的迁移链中；
4. 不是被更新版本替代、删除或显式废弃的实现；
5. 有可执行测试，或可在只读源副本中建立最小行为证据；
6. 不依赖真实数据、真实凭据或被本次排除的外部写操作；
7. 可以在 NEWCaostone 中独立维护和测试。

未同时满足这些条件的能力不算“已有有效功能”，应重新实现或明确排除，不能为了追求表面完整而复制。

### 6.2 首发功能分组

首发产品面按以下职责组织：

- 数据导入：文件识别、字段映射、标准化、质量检查和原子提交；
- 数据版本：版本历史、证据元数据、发布指针和回退；
- 经营分析：被证明有效的销售、广告、库存、成本、利润及目标结果页面；
- 机会分析：被证明有效的产品机会或行动建议页面；
- 新品预测：AI 辅助输入和解释，确定性场景计算；
- 利润归因：确定性 Profit Bridge；
- 数据库问答：白名单查询计划、确定性数据结果、AI 解释、证据和后续问题；
- 行动卡：建议、证据、人工决策、导出和结果复盘；
- 公共 Demo：匿名只读、会话隔离和模拟行动；
- 操作者后台：纯合成数据导入、发布、导出和配置状态。

候选核验后如发现某个旧页面只有外观而没有正式服务、迁移或测试支撑，不将它计入完成范围。

## 7. 来源权威与复用核验门

本节定义后续复用核验方法。本版已执行第 7.6 节所列的设计级只读检查；尚未复制模块、运行候选测试或批准任何实现复用。

### 7.1 只读原则

- CAPTSONE 始终只读；
- 不在 CAPTSONE 安装依赖、生成缓存、运行会写入数据库的任务或修改 Git 状态；
- 需要运行验证时，先在 NEWCaostone 下创建隔离副本或工作树；
- 所有补丁、测试结果、清单和实现只写入 NEWCaostone。
- 不整库复制 CAPTSONE；只复制已经进入复用账本且目标明确的文件。

### 7.2 权威提交

实施开始时先选择一个不可变提交 SHA 作为候选基线，而不是使用会继续移动的分支名称。选择依据按以下顺序：

1. 当前正式运行入口实际引用的提交；
2. 当前迁移链、服务层和前端入口一致；
3. 对应功能的测试在该提交可运行；
4. 后续历史没有显示该实现已被替换、删除或回滚；
5. 不包含只为课程、一次性里程碑或旧 Demo 添加的覆盖层，除非该能力独立满足本次范围。

### 7.3 排除规则

下列对象默认不是复用来源，除非存在明确的运行可达性和版本证据：

- 名称包含 `old`、`backup`、`archive`、`draft`、`review_later` 或类似含义的目录；
- ZIP、导出包、临时工作树和本地复制目录；
- 作业、提交、课程 Demo、一次性诊断和历史里程碑代码；
- 只有文档或截图描述、没有正式运行入口的模块；
- 只有前端壳层、没有正式 API 或持久化支撑的页面；
- 迁移链之外的表结构或失去调用方的服务；
- 后续提交已明确替换或删除的旧版本。

### 7.4 运行可达性检查

每个候选模块必须证明以下链路：

```text
正式应用入口
  → 正式路由或前端入口
  → 服务层
  → 数据访问/迁移对象
  → 可运行测试或最小行为证据
```

单独存在的函数、类、HTML 文件或测试文件都不足以证明模块有效。

### 7.5 复用账本

后续实施应维护 `REUSE_LEDGER.md`，每项记录：

- 功能名称；
- 来源提交 SHA 和文件；
- 正式入口及调用链；
- 迁移依赖；
- 测试证据；
- 后续替换/废弃检查结果；
- 采用、改写或拒绝的决定；
- 在 NEWCaostone 中的目标位置；
- 已知差异和重新验证命令。

未进入复用账本的代码不得被描述为“已验证复用”。

### 7.6 设计级只读检查结果

本版只把以下结果用于产品和前端布局决策，不把它们升级为实现复用证明：

- Action Inbox 设计、前端状态模块和服务在两条 Git 线上的 Git blob 相同；当前权威人工作业状态是 `new → reviewed → approved/dismissed`，Outcome Review 是独立记录且不会把 Action 改成 `completed`。本版完整行动卡沿用该状态骨架，避免另建不兼容状态机。

### 7.7 选择性复用时间盒

为避免在旧项目审计上耗尽上线时间，实施阶段采用以下上限：

| 候选类型 | 单项核验上限 | 超时默认决定 |
|---|---:|---|
| 纯前端组件、样式或无状态工具 | 60 分钟 | 在 NEWCaostone 重写并补测试 |
| 一个完整垂直功能的前端/API/服务 | 2 小时 | 只保留已证明部分，其余重建 |
| 导入、版本、PostgreSQL 迁移等核心数据主干 | 4 小时 | 停止扩大旧库搜索，按本设计重建最小主干 |

时间盒只限制“寻找和证明可复用代码”的时间，不允许跳过目标实现的测试、安全或迁移验证。每次核验结束立即记录 `采用 / 改写 / 拒绝`，不开展无边界全仓审计。

## 8. 数据导入和版本生命周期

### 8.1 数据流程

```text
选择内置纯合成数据或上传纯合成文件
  → 来源确认与内容边界检查
  → 识别报表类型
  → 字段映射
  → 标准化
  → 数据质量检查
  → 多文件原子提交
  → 生成不可变数据版本
  → 确定性分析、证据、AI 和导出
```

### 8.2 合成数据保护

- 内置数据由固定种子或受版本控制的生成规则产生，保证演示可重复；
- 合成店铺、产品、订单和用户标识使用明显虚构的命名空间；
- 上传前由操作者确认文件完全不来源于真实业务；
- 上传检查拦截常见密钥格式、邮箱、电话号码、地址和疑似真实账号标识；
- 自动检查只能作为辅助，不能把真实数据变成允许数据；
- 日志不记录完整表格行或文件内容；
- 公共页面持续显示“合成演示数据”。

### 8.3 原始文件

原始 Excel/CSV 只进入有界临时区：

- 成功提交、排除、失败、取消或超时后删除；
- 不作为长期数据库；
- 不直接发送给 OpenAI API；
- 不出现在日志、错误响应、公开证据或导出路径中。

### 8.4 长期对象

长期保留的演示对象包括：

- 标准化数据版本；
- 导入批次、字段映射和质量结果；
- 确定性分析结果；
- 证据引用和算法版本；
- 操作者行动卡决策；
- 演示导出文件；
- 结果复盘记录。

匿名观众的 Chat Box 对话、结构化查询计划和模拟行动只在演示会话有效期内保留，到期或主动结束后清理；操作者的已确认问答和行动卡可以持久化。原始数据库查询结果不复制成第二套长期事实表，只保存有界结果摘要、证据引用、版本和审计元数据。

### 8.5 原子性与幂等

- 同一批多文件全部成功或全部回滚；
- 每次提交生成唯一批次和数据版本；
- 重放已确认批次不重复累计；
- 疑似重复上传必须阻止或要求明确确认；
- Blob 对象只有在数据库事务成功后才可成为有效版本的一部分；
- 失败信息不暴露路径、连接串、密钥或供应商原始响应。

## 9. 公共版本发布

操作者从完整、通过质量检查的数据版本中手动发布公共预设。

1. 发布只切换当前公共版本指针，不覆盖历史数据。
2. 新会话读取最新已发布版本。
3. 进行中的会话固定进入时的版本。
4. 新发布不改变已有会话的页面、AI 证据或行动卡。
5. 发布失败时继续使用原版本。
6. 操作者可以回退到仍有效的历史版本。
7. 公共版本必须通过零真实数据检查并显示合成数据标识。

## 10. 系统架构

### 10.1 逻辑组件

```text
Azure 公开 HTTPS URL
        │
        ├── 匿名观众路由
        │      ├── 只读仪表盘
        │      ├── 新品预测与利润归因
        │      ├── Ask BizPulse 数据库问答
        │      └── 会话内行动卡模拟
        │
        └── 单一操作者受保护路由
               ├── 合成文件导入与提交
               ├── 数据版本与发布
               ├── 持久行动卡
               └── 演示任务文件导出

应用服务
  ├── PostgreSQL：权威关系状态
  ├── Azure Blob：版本化对象、临时上传和导出
  └── OpenAI API：受证据约束的查询意图、解释和结构化辅助
```

### 10.2 PostgreSQL

PostgreSQL 是持久状态权威来源，数据库变化通过单一迁移链管理。逻辑实体至少承担：

- 操作者演示工作区；
- 导入批次和数据版本；
- 标准化事实及维度；
- 当前公共版本指针；
- 匿名 Demo 会话；
- AI 会话、消息和安全摘要；
- Chat 查询计划、白名单工具结果摘要、证据和失败状态；
- 新品预测运行和场景；
- 利润桥接运行和归因项；
- 行动卡、修订、决策、导出和结果；
- 分析产物、证据和算法版本。

实体名称在实施计划中与被验证的候选 schema 对齐，但职责分离和证据关联不得删除。

### 10.3 Azure Blob

对象按用途分区：

- 临时上传：短生命周期，到期或处理结束后删除；
- 标准化数据：按数据版本不可变保存；
- 分析与证据：按分析运行和算法版本保存；
- 导出：设置下载期限和清理周期。

Blob 对象通过数据库元数据引用。孤立对象由安全清理任务处理，不能被公共版本指针引用。

### 10.4 隔离

本次不是客户多租户系统，但仍保留最小隔离：

- 唯一操作者工作区；
- 公共查询只绑定当前会话固定的数据版本；
- 会话范围只由服务器 Cookie 解析；
- AI 消息和模拟行动绑定当前会话；
- 操作者写路由使用独立认证守卫；
- 公共 API 不提供上传、发布或通用写能力。

该隔离仅为零真实数据 Demo 设计，不应作为真实客户安全模型引用。

## 11. 新品预测（不接入 Google Trends）

### 11.1 产品定位

新品预测采用“AI 辅助结构化 + 人工确认 + 确定性场景计算 + AI 解释”的组合：

1. AI 可以把操作者输入的虚构新品描述整理为结构化字段；
2. AI 可以从当前合成数据版本中推荐相似 SKU 候选；
3. 操作者确认或调整相似 SKU；
4. 确定性算法计算低、基准、高三种情景；
5. AI 解释驱动因素、证据和限制，不生成权威数字。

AI 不联网抓取竞品信息，不补造市场规模、价格、销量或趋势。本版不导入或调用 Google Trends。

### 11.2 输入

预测输入至少包括：

- 虚构新品名称、品类和属性；
- 计划上架日期；
- 售价、商品成本和预计折扣；
- 首批库存、MOQ 和补货提前期；
- 预计广告预算；
- 操作者确认的相似 SKU；
- 预测时点可用的合成历史数据；
- 缺失字段和显式假设。

### 11.3 输出

首发输出：

- 7、30 和 90 天销量区间；
- 7、30 和 90 天收入区间；
- 贡献利润区间；
- 库存覆盖和建议首批数量；
- 低、基准、高三种情景；
- 置信度等级及计算原因；
- 主要正向和负向驱动因素；
- 相似 SKU、数据版本、算法版本和假设引用。

### 11.4 计算边界

- 数值来自版本化、可重复的确定性计算；
- AI 生成的结构化字段必须经 schema 校验；
- 相似 SKU 未经操作者确认不能成为最终预测依据；
- 没有足够相似数据时使用明确标注的品类基线并降低置信度；
- 输入缺失时显示缺失字段，不静默填入虚构精确值；
- 每次预测保存输入快照、场景参数、算法版本和输出证据。

### 11.5 评估

使用合成历史中的隐藏新品窗口执行回测，至少报告：

- MAE 或 WAPE；
- 低高区间覆盖率；
- 相似 SKU 变化对结果的敏感性；
- 缺失输入和极端值稳定性；
- 相同输入和算法版本的可重复性。

回测仅证明合成 Demo 行为，不代表真实市场预测准确率。

### 11.6 在线数据边界

- 不提供 Google Trends CSV 上传或导入入口；
- 不调用 Google Trends 官方或非官方 API；
- 不使用 `pytrends`、网页抓取、搜索引擎结果页或浏览器自动化补数；
- 不把模型一般知识当作实时市场趋势；
- 如复用现有 Product Opportunity 页面，只读取内置、版本化、纯合成的市场快照，并明确显示 `Synthetic market snapshot / 合成市场快照`；
- 在线市场信号未来如要加入，必须单独设计来源、许可、刷新、缓存、失败和证据规则，不在本次上线范围中暗中接入。

## 12. 利润归因与 Chat 问答入口

### 12.1 权威利润口径

首发使用贡献利润作为问答默认口径：

```text
净销售收入
  - 商品成本
  - 平台费用
  - 广告费用
  - 退款及退款相关损失
  - 物流与履约费用
  - 税费（数据存在时）
  ± 汇率影响
  - 其他已映射变动成本
  = 贡献利润
```

缺少某一项时不得默认其为零；必须标记为“缺失”或“未映射”，并降低结论完整度。

### 12.2 Profit Bridge

比较当前期间与等长上一期间或显式选择的基准，确定性分解：

- 销量变化；
- 售价和折扣变化；
- 产品组合变化；
- 广告费用变化；
- 退款变化；
- 物流和履约变化；
- 平台费率变化；
- 商品成本变化；
- 汇率变化；
- 其他已映射成本；
- 未解释或未映射差额。

桥接项之和必须在规定容差内回到总利润变化。无法回桥的差额必须单独显示，不能分摊到看似合理的原因。

### 12.3 证据状态

每个归因项标记：

- `measured`：由当前数据直接计算；
- `derived`：由已批准公式和直接数据推导；
- `assumed`：使用明确的演示假设；
- `unknown`：证据不足或未映射。

AI 不得把 `assumed` 或 `unknown` 描述成已测量事实。

### 12.4 利润页问题入口

利润页提供推荐问题和 `Ask about this / 就此提问` 次级入口，统一打开第 13 节的 Chat Box，并把当前 Profit Bridge 的服务端范围引用作为上下文，不另建第二套问答服务。问答只使用选定 Profit Bridge、其结构化归因项和证据。回答默认结构：

1. 结论；
2. 利润变化总额；
3. 前三项驱动因素；
4. 数据版本、比较窗口和证据引用；
5. 置信度、缺失项和未解释差额；
6. 可供人工考虑的下一步行动。

支持的问题包括“为什么利润下降”“广告是否抵消了收入增长”“哪个 SKU 贡献最大”“如果排除汇率影响会怎样”。问题超出当前结构化证据时明确拒答或要求调整筛选条件。

## 13. AI 服务与数据库 Chat Box 设计

### 13.1 模型和配置

- 首发模型固定为 `gpt-5.4-mini-2026-03-17`；
- 推理强度固定为 `reasoning.effort: low`；
- 模型和推理强度只由服务器配置执行，浏览器不能指定或覆盖；
- 更换模型必须先通过相同评估集并提升设计版本；
- 全站使用操作者为本次 Demo 提供的一把专用临时 OpenAI API Key；
- API Key 只在服务器环境变量或 Azure App Service 服务器设置中，不进入 Git、数据库、前端、日志或导出物；
- 本次不建设 Key Vault、Managed Identity、自动轮换或高级密钥审计；
- 演示结束后先撤销该 Key，再从 Azure 服务器设置中删除；
- 请求不发送原始上传文件，只发送最小结构化合成上下文；
- 不启用 Web Search、File Search、Code Interpreter 或外部工具；
- 模型不能访问数据库连接、ORM 会话、表结构发现接口或任意 SQL 执行器。

### 13.2 资源边界

- 单次输入最多 2,000 字符；
- 单次输出最多 1,200 tokens；
- 每个会话同时只有一个在途 AI 请求；
- 上下文只保留最近 4 轮和安全摘要；
- 观众在有效会话内不显示或设置固定的正常提问次数额度；
- 服务器仍对异常高频调用、全应用并发和时间窗口请求量限流；
- 同一网络的会话创建限制必须允许至少 15 位观众在课堂网络中进入；
- 部署时设置明确的日/月预算上限，达到上限时 AI 失败关闭；
- 观众不能选择任意模型、工具或数据版本。

预算金额是上线配置值，不改变本设计边界；没有预算上限时不得开放公共 AI。

### 13.3 证据约束

AI 只可以使用：

- 当前会话固定的合成数据版本；
- 已完成的确定性分析；
- 新品预测输入、场景和证据；
- Profit Bridge 及归因项；
- 行动卡的结构化字段；
- 经过服务端白名单查询生成的有界结构化结果和证据别名。

AI 不可以：

- 修改标准化数据或确定性结果；
- 自行批准行动卡；
- 执行外部平台操作；
- 编造数字、来源、竞品或真实市场事实；
- 生成、建议或执行 SQL、DDL、DML，扫描任意表，或请求数据库凭据；
- 访问其他观众的对话；
- 把 Demo 输出描述为真实经营建议。

证据不足时回答“当前合成数据不足以支持该结论”，并说明缺少什么。供应商故障、超时或预算耗尽时只关闭 AI 层，确定性页面继续可用。

### 13.4 Chat Box 的产品范围

名称为 `Ask BizPulse / 数据问答`。它询问的是“当前已发布合成数据版本中的经营事实和已完成分析”，不是数据库管理工具。首发支持：

- KPI 查询、同口径期间比较和趋势；
- 销售、广告和 SKU 排名；
- 库存风险、库存覆盖和补货结果；
- 成本、Contribution Profit 和 Profit Bridge 驱动因素；
- 数据版本、覆盖、质量、缺失和证据来源；
- 新品预测的输入、相似 SKU、三情景和限制；
- 行动卡状态、决策、导出和合成结果复盘。

首发不支持任意表查询、任意 JOIN、数据库 schema 问答、原始行批量导出、全文搜索、修改数据、外部平台操作或超出已完成分析的因果推断。

### 13.5 安全查询链路

```text
用户问题或推荐问题 ID
  → 服务端固定会话范围与能力目录
  → 严格结构化查询计划
  → 意图、字段、筛选、时间窗口和结果上限校验
  → 服务端自有的参数化只读查询/确定性分析函数
  → 有界结构化结果、数据状态和证据别名
  → AI 只解释该结果
  → 服务端重新合并权威数字与证据
  → Chat 回答卡
```

自由文本问题最多触发一次计划调用和一次回答调用；推荐问题使用服务器预定义计划，可跳过计划调用。两类路径都不自动重试。模型只看到闭合的能力目录和请求本身，不能看到 PostgreSQL schema、凭据或 SQL 模板。

查询执行必须满足：

- 会话、数据版本、工作区、公共/操作者身份和可选商店范围均由服务器派生；
- 只调用注册的 `QueryTool`，每个工具拥有固定输入 schema、参数化查询和固定输出 schema；
- PostgreSQL 使用只读事务，单次查询默认 5 秒超时；
- 单次最多返回 25 个聚合事实、20 个排名项、10 个证据别名和两个比较期间；
- 不把模型文本拼接进 SQL，不执行模型返回的 SQL 或表达式；
- 结果超过上限时返回聚合、分页建议或要求缩小范围，不截取后伪装成完整答案。

### 13.6 白名单查询工具

首发工具目录固定为：

| 工具 | 允许回答 | 禁止行为 |
|---|---|---|
| `metric_lookup` | 已定义 KPI、期间值、变化和口径 | 自定义公式或任意列 |
| `trend_compare` | 受支持指标的有界趋势和等长期间比较 | 任意时间扫描 |
| `sku_rank` | 销售、广告、利润、库存或补货的 Top/Bottom SKU | 原始 SKU 全表导出 |
| `profit_bridge_explain` | 已完成 Profit Bridge 及驱动因素 | 从明细即席生成新利润口径 |
| `inventory_risk_lookup` | 已完成库存风险、覆盖和证据 | 修改库存或阈值 |
| `forecast_lookup` | 已完成新品三情景、相似 SKU 和假设 | 生成在线市场数据 |
| `data_quality_lookup` | 版本、覆盖、缺失、映射和质量状态 | 文件内容或内部路径 |
| `action_card_lookup` | 卡片、修订、决策、导出和结果状态 | 审批、导出或改状态 |

工具目录由服务器版本化。新增工具属于设计和安全范围变更，不能只通过提示词上线。

```json
{

  "answer": "...",
  "scope": {
    "dataset_version": "...",
    "stores": ["..."],
    "period": {"start": "...", "end": "..."},
    "currency": "BRL"
  },
  "facts": [
    {
      "fact_ref": "fact-001",
      "label": "...",
      "value": "...",
      "evidence_state": "measured | derived | assumed | unknown",
      "evidence_refs": ["..."]
    }
  ],
  "limitations": ["..."],
  "suggested_questions": ["..."],
  "action_card_draft_eligible": false
}
```

数值、单位、范围、数据版本、证据状态和证据引用由服务器提供，模型只能生成 `answer`、对既有 `fact_ref` 的解释和受限后续问题。未知、重复、遗漏或新增 `fact_ref` 的模型输出失败关闭，不向用户显示为成功答案。回答使用纯文本结构，前端统一转义，不渲染模型 HTML。

### 13.8 对话与会话

- 页面显示当前固定的数据版本、商店、期间、币种和合成数据标识；
- 观众不能通过提示词改变工作区或数据版本；允许的筛选变更必须使用服务器提供的显式控件；
- 上下文只向模型发送最近 4 轮的安全摘要、当前问题和当前结构化结果；
- 页面可显示本会话内更多历史，但旧消息不自动进入模型上下文；
- 观众消息、结果和摘要绑定 Demo 会话，到期或主动结束后删除；
- 操作者可选择把某一问答保存为审计记录；未保存的普通对话仍按会话清理；
- 日志只记录请求 ID、状态、耗时、工具名、数据版本和 token 使用量，不记录完整问题、回答或数据库结果；
- 输入若疑似包含密钥、邮箱、电话、地址、真实账号或连接串，拒绝发送并提示只询问当前合成数据。

### 13.9 从回答创建行动卡草稿

只有白名单工具结果满足行动卡类型、完整数字和证据要求时，回答才显示 `Create draft action / 创建行动草稿`。点击后服务器重新解析当前数据版本和证据，创建状态为 `new` 的行动卡；AI 文本不能直接成为权威数量、预算、日期或影响值。

- 匿名观众创建会话内模拟草稿；
- 操作者创建持久 `new` 行动卡；
- Chat 本身不能批准、调整、驳回、导出或记录结果；
- 创建草稿是第二次明确用户操作，回答生成不自动创建卡片；
- 证据或数据版本在点击前变化时拒绝创建，并要求重新提问或刷新。

### 13.10 Chat API、状态和持久化边界

首发 API 采用一条用户提交对应一条逻辑 turn 的最小表面：

```text
GET    /api/v1/ai-chat/turns
POST   /api/v1/ai-chat/turns
GET    /api/v1/ai-chat/turns/{turn_id}
POST   /api/v1/ai-chat/turns/{turn_id}/action-card-drafts
DELETE /api/v1/ai-chat/session
```

- `POST /turns` 接受 `question` 或服务器发布的 `recommended_question_id` 二选一，并要求 `Idempotency-Key`；
- 公共会话、操作者身份、工作区和已固定数据版本均由 Cookie/服务端上下文派生，不接受 owner、session 或任意 artifact ID；
- exact replay 返回同一 turn，不产生额外计划、查询或模型调用；同一 key 不同请求返回冲突；
- 处理状态为 `planning`、`querying`、`answering`、`answered`、`clarification_required`、`unsupported`、`failed` 或 `outcome_unknown`；
- 请求传输后无法判断模型是否接收时记录 `outcome_unknown`，不自动重试；
- `DELETE /session` 只清理当前观众会话的 Chat 和模拟行动，不影响公共数据、操作者记录或其他会话。

迁移控制的概念实体包括：

- `ai_chat_turns`：安全问题文本或推荐问题 ID、状态、服务端范围、数据版本、计划/输出版本、幂等摘要和时间；
- `ai_chat_tool_runs`：工具名、校验后参数、结构化结果摘要、结果 hash、超时和状态；
- `ai_chat_evidence`：turn、fact_ref、分析运行和证据别名的不可变关系；
- `ai_chat_attempts`：计划/回答阶段、模型、token、状态和安全错误码；
- `ai_chat_saved_records`：仅操作者显式保存的问答审计记录。

数据库不保存 API Key、数据库凭据、SQL、完整 provider 请求/响应、原始上传行或未经过滤的日志副本。观众记录通过现有 Demo 会话外键和到期清理收口；操作者未显式保存的普通 Chat 同样按会话清理。

## 14. 完整行动卡

### 14.1 字段

每张行动卡至少包含：

- 卡片类型和建议行动；
- 适用对象、期间和范围；
- 数字依据和预期影响；
- 置信度和限制；
- 数据版本、分析运行和证据引用；
- 建议数量、预算、日期或阈值；
- 当前状态和最后修订版本；
- 决策人、决策时间和决策理由；
- 导出状态及导出物引用；
- 复盘日期、实际合成结果和结果判断；
- 来源类型：确定性规则、新品预测、Profit Bridge、Operating Advice 或 Chat Box 草稿；
- 来源 Chat turn、查询工具和回答版本（仅 Chat 来源时）。

### 14.2 状态机

```text
new
  → reviewed
      ├── approved
      └── dismissed

reviewed --adjust--> 新的不可变修订（仍为 reviewed）
approved --export--> 独立导出记录（Action 仍为 approved）
approved --outcome review--> 独立结果复盘（Action 仍为 approved）
```

- 状态变化由明确服务端命令执行；
- 不允许客户端直接覆盖最终状态；
- `new` 不能跳过 `reviewed` 直接进入终态；
- 调整产生新的不可变卡片修订，不覆盖原建议，并保持 `reviewed` 等待最终决定；
- `dismissed` 在界面中表达“驳回”，必须保留理由和原证据；
- `approved` 只表示人工同意跟进，不表示执行或完成；
- Chat 只能创建 `new` 卡片，不能跳过 `reviewed`；
- 导出是独立记录，不等于外部平台已执行，也不改变 Action 状态；
- Outcome Review 是独立、可修订且证据固定的人工结论，不修改原预测、原决策或 Action 状态。

### 14.3 观众模拟

观众的批准、调整和驳回只存在自己的临时会话中：

- 不修改公共卡片模板；
- 不生成真实任务；
- 不影响其他会话；
- 不调用外部平台；
- 随会话结束或过期清除。

### 14.4 操作者闭环

操作者决策持久化，并可导出演示采购或广告任务文件。首发闭环为：

```text
建议
  → 数字与证据
  → 人工批准/调整/驳回
  → 演示文件导出
  → 人工记录合成结果
  → 结果复盘
```

## 16. 安全基线

即使只使用合成数据，公开 Demo 仍必须保留：

- Azure HTTPS；
- 服务端操作者认证和路由守卫；
- HttpOnly、Secure、适当 SameSite 的 Cookie；
- CSRF 防护；
- 不可预测的观众会话标识；
- 文件类型、大小、字段和内容边界检查；
- 临时文件生命周期清理；
- 上传文件名和公式注入防护；
- AI 输入、输出、并发、频率、超时和总预算限制；
- Chat 意图、查询工具、字段、时间窗口、返回规模和只读事务白名单；
- 永不执行模型生成的 SQL，永不把数据库 schema、凭据或连接交给模型；
- 对提示注入、SQL 注入、越权范围、跨会话引用和大结果查询失败关闭；
- 日志脱敏，不记录密钥、完整文件内容或完整自由文本对话；
- 错误响应不暴露内部路径、堆栈、连接串或供应商响应；
- 数据库和 Blob 凭据只存在服务器配置；
- 管理接口和诊断接口不公开。

本基线只支持零真实数据 Demo，不是 Production 安全认证。

## 18. 异常和恢复

| 场景 | 预期行为 |
|---|---|
| 上传疑似包含真实标识 | 阻止提交，要求移除；不得自动“脱敏后继续” |
| 任一导入文件失败 | 整批回滚，不产生部分数据版本 |
| 重复提交 | 幂等返回原结果或阻止重复累计 |
| Blob 成功而数据库失败 | 对象保持不可发布并进入安全清理 |
| 发布失败 | 保留原公共版本 |
| 应用重启 | 从 PostgreSQL 恢复未过期会话和持久状态 |
| 观众刷新 | 恢复同一会话、数据版本、对话和模拟行动 |
| 会话过期 | 清理临时状态并引导创建新会话 |
| AI 超时或供应商故障 | 显示 AI 暂不可用，确定性分析继续工作 |
| 达到 AI 预算或限流 | 失败关闭 AI，不绕过预算、不伪造回答 |
| API Key 无效 | 操作者看到安全配置状态；公共页面不泄露细节 |
| Chat 问题含糊或需要未授权范围 | 返回澄清问题或 `unsupported`，不查询数据库 |
| Chat 计划包含未知工具、字段或筛选 | 在数据库访问前拒绝，不做模型自动修复或重试 |
| Chat 查询超时或结果过大 | 终止只读事务，要求缩小范围，不能返回截断后伪装的完整答案 |
| Chat 受到提示注入或 SQL 注入 | 视为普通文本并由严格 schema/白名单拒绝；绝不执行其中命令 |
| Chat 回答模型失败 | 保留确定性查询结果，显示权威事实卡或安全失败，不伪造自然语言答案 |
| Chat 点击创建草稿时证据已变化 | 不创建行动卡，要求刷新或重新提问 |
| 归因无法回桥 | 显示未解释差额，不强行分摊 |
| 预测证据不足 | 降低置信度或停止给出精确预测 |

6. `Hosted verified`：Azure 实际配置和浏览器路径通过；
7. `Azure Demo accepted`：本设计的全部 Demo 验收证据通过。

这些状态不能互相替代。URL 可访问不等于持久化、AI、恢复或完整 Demo 已验收；任何一级都不代表 Production readiness。

## 20. Azure Demo 完成定义

只有以下条件全部满足，才称为“Azure Demo 已验收”：

- 单一操作者可以导入纯合成文件并原子提交；

## 23. 主要风险与控制

| 风险 | 控制 |
|---|---|
| 脱敏真实数据被误当合成数据 | 明确禁止一切真实来源衍生数据；内置固定合成数据优先 |
| 旧界面或废稿被当成有效功能 | 不可变提交、运行可达性、迁移链、替换历史和测试五重核验 |
| 为节省时间复制过时代码 | 复用账本逐项记录；证据不足时重建而不是猜测 |
| 在分叉 Git 线之间拼接前端 | 精确 SHA/blob、正式入口和完整浏览器回归；不从工作树或时间戳猜最新 |
| 多文件导入产生半成品 | 原子提交、幂等、回滚和版本化 |
| 新发布影响正在演示的人 | 会话进入时固定数据版本 |
| AI 编造数字或真实市场事实 | 确定性数字为权威、最小结构化上下文、证据不足拒答 |
| Chat 被当作 SQL 控制台 | 封闭 QueryTool、服务端范围、参数化只读查询；绝不执行模型 SQL |
| 提示注入诱导越权或改证据 | 查询前严格计划校验，回答后按 fact_ref 合并，未知引用失败关闭 |
| 观众在自由文本中输入真实信息 | 明确提示、敏感模式拦截、会话 TTL、日志不记录完整文本 |
| Google Trends 又通过旧模块被带入 | 复用账本明确拒绝旧 API/CSV 适配器，网络测试证明无该请求 |
| 公共 AI 费用失控 | 输入输出边界、会话限流、全局并发和强制预算上限 |
| 利润归因看似合理但无法对账 | Profit Bridge 回桥和未解释差额显式展示 |
| 行动卡被误解为已执行 | 导出与执行状态分离，界面持续标注模拟 |
| Azure URL 可访问但状态会丢失 | PostgreSQL/Blob 实际配置、重启读回和恢复验证 |
| Demo 被宣传为 Production | 文档、页面和交付状态持续标注 Demo-only/non-Production |
| 工作目录被缓存、备份和整库复制污染 | 固定目录、`.gitignore`、受控临时区、批次 Git 状态和大文件检查 |
